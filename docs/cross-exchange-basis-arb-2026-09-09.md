## 3. 这个基差为什么存在、会不会被吃掉(要求 2)

### 3.1 分解:基差 = 指数差 + 溢价差

恒等式(实测逐行成立):

```
basis = (gate价 − bn价)/bn价
      = [(gate价 − gate指数)/gate指数] − [(bn价 − bn指数)/bn指数] + (gate指数 − bn指数)/bn指数
      =            gate溢价           −           bn溢价          +        指数差
```

全样本实测(45 轮):**|指数差| 中位 1.47 bps、|溢价差| 中位 2.86 bps、|基差| 中位 4.16 bps。**
逐个看,两种成因都真实存在,而且**不同合约主导项完全不同**:

| 主导项 | 例子(41 天历史) | 含义 |
|---|---|---|
| **指数差** | BZ(基差 −9.28,其中指数差 −6.95,占 75%)、CL(−7.38 / −5.25,71%)、OPENAI(今日 −25.92 / −25.61,99%) | **两所对同一个标的的"公允价"算得就不一样**(成分交易所、取样方式不同)。这不是错价,是两个不同的标尺。**它没有任何理由收敛。** |
| **溢价差** | **BNB(基差 −10.74,指数差 +0.00,溢价差 −10.74)**、UAI(−17.20 / +0.40 / −17.78) | 两所指数一致,**是 gate 的永续本身持续贴水**。这是真的供需差,理论上被资金费拉住。 |

**这条分解直接否掉了"跨所价差套利"这个说法的一半**:凡是指数差主导的(BZ/CL/OPENAI),
你买的和卖的**根本不是同一个价格口径**,把它当同一标的对冲,你持有的是"两个指数之差"这个风险,
不是无风险价差。

### 3.2 那它会不会被资金费吃掉 —— 资金费差实测

**先摆机制**:两个永续都没有到期日,**没有任何机制强制两所价格收敛**。
唯一把仓位变成现金的通道是资金费:持有 [gate 多 / binance 空] 的净收 = −gate费 + binance费。

**截面相关性(45 轮 × 75 合约,同一时刻)**:

- corr(基差, 资金费差/8h) = **0.257**
- corr(**溢价差**, 资金费差/8h) = **0.467**,斜率 0.742

**溢价差和资金费差的相关明显高于基差和资金费差** —— 和 §3.1 的分解一致:
资金费只对"价格 vs 自家指数"负责,对"两家指数谁高谁低"根本不负责。**机制自洽。**

### 3.3 口径裁决

**#14 的正确口径是:跨所 funding carry,不是跨所价差套利。**

理由三条,全部实测:
1. 两个永续都不到期,**不存在强制收敛机制**(机制事实);
2. 基差里 |指数差| 中位 1.47 bps、且在最大的几个候选上占 71%~99%,
   **指数差没有理由收敛**(§3.1);
3. 唯一的现金流是资金费差,而它 29 天日均 +0.16 ~ +0.50 bps、同号率 59%(§3.2)。

数据一到就能直接跑 —— 这是 §5 存在的理由。

### 4.2 规则 v0(建议只在 §4.6 的"影子模式"下跑)

**标的池(每日一次离线重算)**,四条同时满足:

```
① 41天 |基差中位| ≥ 5 bps            (来源:两所 1h K线,§2.4 的算法)
② 41天 同号率 ≥ 90%                   (剔除 OPENAI 这种纯噪声)
③ 41天 振幅 p90−p10 ≥ 3 × 来回成本    (来回成本见 §4.4;双吃单口径 = 75 bps 门槛)
④ 四个 L1 档美元深度中位 ≥ 5 × 单笔名义
```

**实测:今天这个池子是空的。**③ 和 ④ 互斥 —— 振幅 >25bps 的 11 个合约里,
L1 四档都 ≥$2k 的 **0 个**;L1 四档都 ≥$2k 的 24 个合约,振幅中位 **8.5 bps**。
**把这条写成规则的意义正在于:它自己会说"今天没得做",而不是逼人硬选一个。**

**进场**(z 值口径,不用绝对 bps —— 绝对阈值在 41 天里会被基差自身的漂移废掉):

```
b_t   = (gate中价 − bn中价)/bn中价 × 1e4          ← 必须来自 order_book,不是 tickers(§2.2)
μ, σ  = b 在过去 7 天(168 根 1h)的中位数与标准差
z_t   = (b_t − μ) / σ

进场条件(全部满足):
  |z_t| ≥ 2.0
  且 该方向毛空间 > 来回成本 × 1.5                  ← 毛空间用【对手价】算,不是中价
  且 两所 L1 该侧美元深度 ≥ 3 × 单笔名义
  且 两所 order_book 的 update 时间戳与本地时钟差 < 2s
  且 距离任一所的下一个资金费结算 > 10 分钟          ← 结算点前后基差会跳
方向:z_t < 0 → gate 便宜 → 多 gate / 空 bn;z_t > 0 反之
挂单方式:两条腿都【挂单】(gate poc / binance GTX),见 §4.3 —— 吃单腿只用于"救腿"
```

**出场**(先到先执行):

```
① z_t 回到 |z| ≤ 0.3                    → 正常平仓(两腿同时挂单平)
② 持仓 > 48 小时                        → 无条件平(carry 抵不过占用,§3.2)
③ |z_t| ≥ 4.0 且方向不利                → 止损平(基差不收敛,认错)
④ 单腿净敞口 > 单笔名义 × 5%,持续 > 30s  → 立刻市价补平那一腿(§4.3)
⑤ 任一所 order_book 断流 > 5s            → 全平,不等
```

### 4.3 单腿失败 —— 跨所套利的头号杀手,规则必须先写这条

**这是唯一一条我建议"宁可少赚也要照做"的:**

```
两腿都用挂单进场,但【永远先挂流动性差的那一腿】,成交后才挂另一腿。
  ├─ 先挂腿(慢腿)= 两所里 L1 该侧美元深度更小的那个所
  ├─ 慢腿成交(或部分成交)→ 立刻用【吃单】在快腿补等量对冲
  │    这一步不许挂单、不许等价格 —— 对冲的价值高于那 5~7 bps 的吃单费
  └─ 慢腿未成交 → T+15s 撤单,本轮作废(不追价)

净敞口闸(硬闸,fail-closed):
  |gate仓位 + bn仓位|(折基础币)> 单笔名义 × 5%,持续 >30s
    → 市价补平较小的那一腿,并【暂停该 symbol 30 分钟】
  连续 3 次触发 → 停整个策略,等人看

进程级:
  两所都必须挂死人开关(countdown_cancel_all)。gate 合约版已实测存在
  (见 #15 评估 §3.4);binance 侧对应 /fapi/v1/countdownCancelAll —— 未测。

  跨所场景下它更致命:撤了单但两条腿还在,进程死了就是裸奔的方向性仓位。
  **在补上"崩溃后自动平仓"之前,这条线不许上真钱。**
```
