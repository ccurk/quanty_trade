     置信度带胜负累计计数。

   所以还有 c) 的跨轮复现要求。

   入队门槛：【稳定分化】+

   十几个组，不设闸门必被噪音灌满。

   · 首次满足全部门槛的当轮 = 登记（复现计数 0/2，登记轮不计复现）；
   · 此后某轮距上一次计入观测（含登记轮）≥6h（3h 节奏下即至少隔一轮），且当轮

   n<30 的切片一律视为轶事：写台账攒样本，禁止行动。
d) 固定产出：台账【运行日志】必须新增本轮行；【候选队列】按本轮数据更新状态

预注册（任何改动执行前必写；写不出可证伪预期 = 没想清楚 = 不改）
═════════════════════════════════════════════════
与改动同一次 PATCH 原子写入 config：
  config 改动：PATCH body = 改动字段 + "_exp":{...} 一次请求
  apply 代码改动：先 PATCH {"_exp":{...}} 再 POST apply
_exp 格式：{"ts":…,"status":"open","action":…,"hypothesis":"针对哪个病灶",
 "metric":"评判用的唯一指标","expect":"预期方向与幅度","eval_after":"…"}
action 前缀登记制（预算推导依赖它，必须遵守）：
  APPLY: 代码改动（占预算）｜RECOVER: 恢复升档（占预算）｜
  LADDER: 降档/档位维护（豁免）｜ROLLBACK: 快速档回滚（豁免）｜
  E1:-E8: 对应触发器的 config 改动（占预算）
_exp 只放【当前在飞实验】一件事；累积知识/队列/直令全部在台账（层3）。
收窄迁移纪律：从 _exp 移除任何非实验键（如 user_directive_*）前，必须先迁入台账
对应节并确认 push 成功；迁移失败则保留原键。
PATCH 后重读 config 确认 _exp 落库；被平台剥离 → TG 报警"注册表不可用"，
此后预注册以 audit after_json 留痕为准（audit 永久记录每次 PATCH 请求体）。
